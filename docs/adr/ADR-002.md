# ADR-002：核心元数据强类型 API 与通用 TLV 的边界

- 状态：已接受
- 日期：2026-09-06
- 关联规范：METADATA_FORMAT_V1.md；GO_API_DESIGN.md §4

## 背景

`meta.Store` 的 13 类核心对象（Header、Table、Column、PrimaryKey、Index、
UniqueKey、ForeignKey、AutoInc、TableComment、ColComment、View、Function、
VirtualColumn）需要无损映射到 RowPack 磁盘格式。同时格式还要为 Sequence、
Trigger、分区、统计信息以及数据库厂商扩展保留通道，且未知非 Critical 字段
必须无损透传。

## 决策

1. 磁盘统一使用通用 MetadataRecord Envelope + Field TLV，13 类核心对象只是
   `rowpack.meta.v1` 命名空间下 RecordType 1–13 的固定字段映射（FieldID 以
   msgpack tag 为兼容依据做数值稳定编号）。
2. 公开 API 分两层：
   - 通用层：`PutMetadata` / `Metadata` / `ListMetadata`，面向未来对象与厂商扩展。
   - 强类型层：`PutCoreMetadata` / `CoreMetadata`，直接表达
     `Header`、`Tables`、`Columns`、`PrimaryKeys`、`Indexes`、`UniqueKeys`、
     `ForeignKeys`、`AutoInc`、`TabComments`、`ColComments`、`Views`、
     `Functions`、`VirtualColumns` 13 个固定列表，不依赖外部项目的 Go 类型。
3. 强类型层是通用层的视图：列表顺序、复合 PK/FK 的逐列 KeySeq、SafeString 原文、
   未知非 Critical 字段透传都在这两层之间保持一致。
4. Go `int` 语义字段在公开模型统一使用 int64，磁盘固定 i64，消除平台宽度差异。
5. 核心表/列记录由派生 Schema 视图解释 TypedTuple 行，不额外保存 SchemaIndexEntry。

## 后果

- 新增标准扩展（1024–65535）和厂商类型（>= 65536）不改外层 Block 格式。
- 未知 Critical 字段/记录返回 `ErrMetadataUnsupported`；未知非 Critical 字段
  在再次写出时字节级无损保留。
- 强类型层与磁盘格式通过映射表双向测试保护（M9 golden fixture）。

## 备选

- 磁盘直接固化强类型 Schema Record：无法承载厂商扩展与无损透传。
- 强类型层复用外部 `meta.Store` 结构：产生外部依赖并耦合方言实现。
