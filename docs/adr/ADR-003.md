# ADR-003：v2 单文件复用 IndexTxn，保持单行读取路径

- 状态：已接受（2026-09-08 修订）
- 关联规范：[BINARY_FORMAT_V2.md](../BINARY_FORMAT_V2.md)

## 背景

v1 的 `.rpk` 保存数据，`.rpi` 保存 Row/Block/Metadata/Snapshot 索引。v1 的 Row Index
是单行 `Get` 性能的重要组成部分；如果完全取消索引，单行读取会退化为扫描和解压候选
Block，与当前使用目标不符。

## 决策

1. v2 只使用一个 `.rpk` 文件，不再创建 `.rpi`。
2. v2 将现有 IndexTxn 原样作为 SnapshotTxn 的一部分追加到同一文件。
3. 保留现有 Row Index、Block Index、Metadata Index、Snapshot Index 和 `index.View`。
4. IndexTxn 位于数据 Block 之后、SnapshotFooter 之前；SnapshotFooter 是最终提交标志。
5. IndexTxn 只保存当前 Snapshot 的增量索引，继续由内存 View 重放和合并。
6. 单行 Get 继续使用 RowID→BlockID→ItemOrdinal，避免 v2 首版性能退化。
7. 批量读取在现有 Row Index 之上按 BlockID 分组、去重和物理排序。
8. v2 直接替代旧格式，不保留旧 reader、双格式分派或迁移 API。

## 后果

收益：

- 单行热读和现有随机读取算法基本保持；
- 数据与索引一次 fsync 提交；
- 消除文件配对、跨文件恢复和双 mmap 生命周期；
- 批量读取可以复用已经成熟的 Row Index 和 Block Cache；
- 改动集中在 Appender、offset、Commit、Open 和 Recovery。

代价：

- 仍有按行增长的索引空间和内存占用；
- v2 首版不解决 v1 的整 Block 冷读放大；
- IndexTxn 仍需要写入和校验；
- 打开时仍然需要重放索引事务。

## 备选

- 完全取消持久化索引：单文件更简单，但单行读取明显退化。
- Page 级新索引：冷读潜力更好，但会同时改变 Block、缓存、加密和恢复路径。
- 保留 `.rpi`：单行性能稳定，但无法消除双文件提交复杂度。

## 评审补充（2026-09-08，详见 V2_DESIGN_RISKS.md）

本决策的落地边界在评审中补充如下，均已写入 [BINARY_FORMAT_V2.md](../BINARY_FORMAT_V2.md)：

- **允许后续 FULL checkpoint**：v1 只允许首个快照为 FULL（writer 强制 id=1）；v2 取消该
  约束，任意时刻可提交 ParentSnapshotID=0 的新 FULL，SnapshotID 取全局递增计数器，
  Depth 重置为 1（R7）。
- **提交权威两维分离**：快照是否提交只看 SnapshotFooter 自身 CRC 与 offset 自洽；
  IndexTxn 绑定失败仅触发内存重建，不影响提交事实；Block 数据损坏始终为硬错（R3）。
- **重放改为逐 snapshot 独立校验/重建/继续**，不能沿用 v1 “首个坏 txn 即停”的重放语义（R2）。
