# ADR-006：S4 Lazy 行索引模式（已撤销）

> Status: Withdrawn before V2 release. Lazy Row Index was removed; production uses Eager shards exclusively. The remainder of this document is historical context.

- 状态：已接受（2026-09-09）
- 关联规范：[FILE_FORMAT_REFACTOR_PLAN.md](../FILE_FORMAT_REFACTOR_PLAN.md) §7 / §15 #4，
  [BINARY_FORMAT_V2.md](../BINARY_FORMAT_V2.md) §6，[ADR-005](ADR-005.md)
- 前置：S3-⑦ 落盘②（排序 Row Index Page + Fence Directory，ADR-005）、S3-⑨（Eager Open
  峰值优化，流式解码直喂 rowShard 构建器）
- 复现：`go test -run '^$' -bench 'Benchmark(OpenMemoryLazy|DeepChainGetLazy)$' -benchmem
  -count=1 ./...`

## 背景

S3 的 Eager 模式在 Open 时把整行索引解码为紧凑 SoA shard（idxB/row ≈ 13）。对超大库或
只做局部读的工作负载，更好的选择是 S4 Lazy：Open 只加载 Row Index Fence Directory
（52 B/页），实际行索引 Page 在首次访问时才 OPEN + decompress + decode，并用一个
bounded LRU 缓存。本 ADR 记录 Lazy 的内存口径、全 API 语义一致性，以及决策点 #4
（深链 I/O 放大）的测量结论。

## 设计（§7.1 / §7.2，对齐 ADR-005）

- 页分区：`buildRowIndexPages` 现在**按表切页**（一个页绝不跨表 run）。这样每页
  `TableID` 是页内唯一表，`MinRowID`/`MaxRowID` 属于该表，Fence 成为
  `(TableID, RowID)` 的**单调**二叉索引。若页跨多表，`MinRowID`（跨表全局最小）
  会随页非单调，Fence 二叉搜索不再可靠。按表切页是合理且合法的磁盘布局（每页仍 ≤
  4096 条、`(TableID, RowID)` 升序）。
- `View.lazy`：非 nil 时持有 `source LazySource` + 每快照的 `[]RowIndexFenceEntry`。
  Eager 的 `rows`/rowShard 在 Lazy 下为 nil。`Row/ResolveRow/RowIter/RowTables/
  LogicalRowCount` 按快照分支：`v.lazy.snapshots[snapshot]` 存在走 Lazy，否则走 Eager
  rowShard（兼容 Lazy 库中某个损坏快照被重建为 Eager 的情况）。
- 只读快照：排他写锁仍保证一次一个写；Lazy 打开是只读侧的读路径，视图不可变并发共享。
- `LazySource`：由 store 实现，签名
  `LoadIndexPage(snapshotID, pageIdx, fence, cache) ([]fileformat.RowIndexEntry, error)`。
  `cache=false` 供 Scan 顺序流式用（不污染随机 `IndexPageCache`）。store 按
  `txnStart + IndexTxnHeaderSize + fence.StoredOffset` 定位页，OPEN（加密）/decompress/
  decode 后按 `StoredOffset` 放入 `IndexPageCache`（LRU，key = 页绝对文件偏移）。
  并发 miss 用 `cache.Group` singleflight 合并。
- 解析：`ParseTxnLazy` 走 `parseStoredBody` + `FenceCaptureSink`：解析并校验 chunk
  目录与 Fence，但**不解码任何页**（`parseRowIndexPages` 见 `FenceCaptureSink` 即短路）。
  故意**跳过正文 CRC 校验**（它覆盖页 raw 字节）——完整性由 `readIndexTxn` 在 Open 时
  做的「存储字节 CRC」加上每页 `PageCRC32C` / AEAD 承担，二者都在首次 Lazy 访问时校验。
- 内存：Lazy 常驻 = 非行 map（快照/块/元数据） + `IndexFenceBytes`（~52 B/页）。
  没有整行索引入驻。`CacheBytes = DataPageCache + ScanWindow + IndexPageCache` 守恒
  （`splitCacheBudget3`；`IndexCacheBytes` 0 = 默认 `total/4`，负 = 禁用）。

## 决策点 #4：深链 Get 的 I/O 放大

测量 `BenchmarkDeepChainGetLazy`，FULL(1000 行) + N 层 DELTA(每层 1 行)，row 落在
快照 1，`Get` 在链尾。指标：readB/op、rawB/op、IndexPageCache loads/op、idxpage-hitpct。
数据块缓存预热（隔离索引链成本）。`IndexCacheBytes=8 MiB`（warm）与 `-1`（cold）。

| 深度 | warm ns/op | cold ns/op | warm readB/op |
| --- | --- | --- | --- |
| 1 | 420 | 20 954 | 772 |
| 8 | 713 | 29 431 | 772 |
| 32 | 1 823 | 22 894 | 772 |
| 128 | 5 019 | 29 969 | 772 |

**结论**：深链下 Lazy 的 I/O 放大**可接受**，无需负查询缓存或 page-level bloom filter。
原因：`ResolveRow` 沿父链逐层调用 `Row(layer, table, rowID)`；Fence 各页带
`MinRowID/MaxRowID`，`lazyIndex.row` 先做 Fence 边界检查，**rowID 落在页 `[Min,Max]`
之外即返回「未命中」且不加载页**。因此只有「该层的 RowID 范围确实覆盖目标行」的层才
需要读一页；一个每层 1 行的 DELTA 链，绝大多数层的 `rowID < MinRowID` 或 `> MaxRowID`
被边界检查滤掉，cold ns 在 1→128 层几乎拉平（~20–30 µs，不随层数线性放大）。每层的
Fence 二叉搜索 + 极小页事务成本相对恒定。且数据块缓存命中后 readB/op 恒定 772（只读
数据块），索引页读走 `s.data.ReadAt`，不放大数据面读数。

## 内存验证

`BenchmarkOpenMemoryLazy`（1M 行 geomMixed）：fenceB/row = 0.0127（目标 ≤ 0.25，
期望 ≤ 0.1），fenceMB ≈ 0.012，idxMB ≈ 0.030。Open 的编码工作已经流式（S3-⑨），
Lazy Open 本身 `B/op` ≈ 0.23 B/row（无页物化、无 shard 构建）。

## 全 API 一致性

`TestLazyMatchesEager`：同一文件分别以 Eager/Lazy 打开，对每个快照×表用
`Get/Scan/Exists/Tables` 捕获可见状态并逐行比对（含跨越多页的大表、跨表页、DELTA 链、
超大行）。此外 `go test -race` 通过。

## 决策

1. **Lazy 模式落地**：`IndexMode`（`IndexEager` 零值 / `IndexLazy`）+ `IndexCacheBytes`，
   `SplitCacheBudget3` 守恒；`Open` 只加载 Fence。
2. **决策点 #4**：深链 Lazy Get I/O 放大可接受（Fence `[Min,Max]` 边界过滤 + 页缓存），
   **不引入**负查询缓存或 page-level bloom filter（收益不足以覆盖内存+CPU）。
