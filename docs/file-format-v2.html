Single-File Binary Format Reference

RowPack v2 单文件格式
字节级规范速览

RowPack 是嵌入式二维表存储引擎。v2 格式将数据块与每快照 IndexTxn 索引流交错追加在同一个 <base>.rpk 文件中，由快照末尾的 SnapshotFooter 作为唯一提交权威 —— 数据、索引与提交标志在一次 fsync 中原子落盘。本文档按字节梳理全部磁盘结构，与 internal/fileformat 实现一一对应。

Magic ROWPACK2 Major 2 · Minor 0 字节序 Little-Endian 对齐 8 字节 校验 CRC-32C (Castagnoli) 压缩 Zstandard 加密 AES-256-GCM 写入模型 Append-Only
01

格式总览

一个 .rpk 文件 = 一个 128 字节 FileHeader + 若干个 SnapshotTxn（+ 可能存在的未提交尾部）。 每个 SnapshotTxn 承载一个不可变快照（FULL 或 DELTA）：先写数据块，再写内嵌 IndexTxn，最后以固定 144 字节的 SnapshotFooter 收尾并原子提交。

FileHeader128 B
SnapshotTxn 1数据 + 索引 + Footer
SnapshotTxn 2…
SnapshotTxn N…
未提交尾部
FileHeader 128 B · Magic “ROWPACK2”
文件身份与全局默认值（UUID、版本、能力位、块大小、压缩、加密参数）。创建后永不更新。
SnapshotTxn × N 每个 = 一个原子提交的快照
快照 ID 全局递增；FULL 可在任意时刻重新提交（Depth 重置），DELTA 沿父链解析可见性。
① SnapshotHeader — 96 B，“RPKSNAPH”，快照类型 / ID / 父 ID / 首 BlockID
② Blocks … — [BlockHeader 64 B (“RPKBLOCK”) + 压缩(→加密) Payload] × M，Rows / Metadata 两类
③ IndexTxn — “RPITXNBH” 头 → 分块条目体 → 明文块目录 → “RPITXNEF” 尾
④ SnapshotFooter — 144 B，“RPKSNAPF”，唯一提交权威，绑定全部区间 offset 与 CRC
[可选] 未提交尾部 最后一个有效 Footer 之后的一切
读写打开时截断（先退映射再截断）；只读打开时忽略并报告；其中任何数据 / 索引都不可见。
🔑 提交权威（R3）
快照是否已提交，只看 SnapshotFooter 自身：FooterCRC32C 校验通过，且其记录的 offset 自洽并在文件范围内。 BlocksCRC32C / IndexTxnCRC32C 绑定失败只影响索引可用性（触发内存重建），不改变提交事实； 但 Block 数据本身的损坏（块头 / 密文认证 / 解压长度 / Raw CRC）是硬错误，绝不跳过。
02

全部 Magic 均为恰好 8 字节 ASCII。v2 数据文件 Magic 有意区别于 v1 预发布的 ROWPACKD， 使 v2 打开器在前 8 字节即拒绝 v1 文件。索引流没有独立 Magic —— 它内嵌在数据文件中。

CRC 规则：每个固定结构的 CRC-32C 覆盖整个结构，且计算时将其自身 CRC 字段视为 0（解码侧按“字段前段 + 4 字节 0 + 字段后段”三段拼接计算，安全兼容只读 mmap）。

固定结构字节布局

04

行数据编码（Rows Block）

一个 Rows Block 只属于一个快照和一张表。写入顺序固定：行载荷 → Zstd 压缩 →（可选）AES-256-GCM 加密， 读取时逆序还原。解压后的载荷结构为：

RowsPayloadHeader · 32 B→ RowDirectoryEntry × ItemCount（按写入顺序）→ RowRecordHeader + 记录体 × ItemCount

TypedTuple v1 行编码

每条非 DELETE 记录的记录体为 TypedTuple v1 编码（RowEncoding=1）： u32 ColumnCount ‖ u32 NullBitmapBytes = ⌈列数/8⌉ ‖ NULL 位图（bit i = 1 ⇒ 第 i 列为 NULL，LSB 在前，末字节高位必须清零）‖ 非 NULL 列按 Schema 顺序依次编码的值。解码后不允许存在尾部剩余字节。 DELETE 记录携带 RowEncoding=0、RowLength=0、RowCRC=0，无记录体。

05

元数据编码（Metadata Block）

Schema 与引擎自产元信息以通用 TLV 记录写入 Metadata Block（命名空间 rowpack.meta.v1）。 引擎自身冻结两类记录：RecordTable=2（表）与 RecordColumn=3（列）—— DefineSchema 即通过它们把 Canonical Schema 写成引擎“自产自销”的数据。 载荷结构：PayloadHeader(32B, “RPKMETAP”) ‖ 目录项×N ‖ 记录体区； DELETE 目录项必须 offset/length/CRC 全 0。记录体 TLV 的字段值类型（WireType）：

WireType编码WireType编码
1Bool6ObjectRef
2Uint7StringList
3Sint8ObjectRefList
4String9Expression
5Bytes10FieldSet

字段标志位：FieldFlagCritical = 1<<0、FieldFlagRepeated = 1<<1；记录 / 字段带 Critical 位时，未知记录或字段必须视为错误。

06

IndexTxn 与分块（Chunking）

每个已提交快照恰好对应一个内嵌索引事务，位于该快照全部数据块之后、SnapshotFooter 之前。 IndexTxn 是派生的导航结构：提供 (SnapshotID, TableID, RowID) → BlockID, ItemOrdinal 的行定位、 块定位与快照摘要；损坏时可以从本事务的数据块在内存重建。

IndexTxnHeader · 80 B（明文）→ [IndexChunkHeader 64 B + 存储态载荷] × M→ IndexChunkDirectory · 32 B × M（明文）→ IndexTxnFooter · 80 B
📐 区间权威校验（R8）
每个 txn 必须满足 IndexTxnEnd = IndexTxnStart + 80(IndexTxnHeader) + BodyBytes + 80(IndexTxnFooter)， 且 SnapshotEndOffset = IndexTxnEndOffset + 144(SnapshotFooter)；任一不满足即视为损坏。 BodyBytes 计的是 Header 与 Footer 之间的存储态字节（分块 + 目录，加密时含 GCM tag）—— 明文与加密 Store 语义一致，扫描器无需理解分块即可跳过整个事务。 DataSnapshotEnd 沿用 v1 语义：指向 SnapshotFooter 之后（即整个 SnapshotTxn 的结束，IndexTxn 属于该范围）。

分块参数

  • 条目按 Kind 分流（1 Snapshot / 2 Metadata / 3 Block / 4 Row），各自切成多个块；默认目标：4096 条/块 或 256 KiB/块。
  • 每块独立压缩（None/Zstd）与独立认证（加密 Store 下每块单独 AES-GCM 封装）。
  • 解析硬上限（防压缩炸弹，分配前强制）：EntryCount ≤ 2²⁰，RawBytes ≤ 16 MiB，StoredBytes ≤ 16 MiB。
  • 块目录为明文（即使加密 Store），无键即可定位分块；仅暴露块大小与条目数，目录自身无 CRC（由 Footer 区域 CRC 与各块头 CRC 覆盖）。

四类索引条目

行索引继续按层提供按 RowID 有序的分片：范围查询对分片二分定位 span 即等价于 envelope 过滤，零额外内存（R14 决议）。 SnapshotIndexEntry 中的 DataEnd 指向 SnapshotFooter 之后，重放校验用 footer = DataEnd − 144 直接取回提交标志。

07

提交 · 打开 · 恢复

SyncCommit 提交协议（单次 fsync）

  1. append SnapshotHeader“RPKSNAPH”，96 B，快照类型 / ID / 父 ID / 首 BlockID / WriterNonce
  2. append Metadata / Rows Blocks逐块：64 B 块头 + 压缩（→加密）载荷；BlockID 单调递增，永不改写
  3. build & append IndexTxn构建分块条目体 + 明文块目录；offset 在此刻解析定案
  4. append SnapshotFooter144 B；BlocksCRC32C = 按物理写序拼接各块 HeaderCRC32C（4 B×N）的 CRC；IndexTxnCRC32C = 整个事务存储态字节的 CRC
  5. fsync 单文件从此刻起失败属于“结果未知”：调用者按 SnapshotID 查询，不得盲目重放非幂等业务
  6. 原子发布 index.View进程内可见性切换
  7. 返回成功AsyncCommit 顺序相同但不主动 fsync；掉电允许丢失最近提交

Abort：没有 SnapshotFooter 的尾部不可见；读写模式可立即截断到 SnapshotHeader 之前，或留待下次 Open 时截断。

物理扫描协议（R1）—— 四类固定结构

遇到的结构Magic扫描动作
SnapshotHeaderRPKSNAPH开始一个新 SnapshotTxn
BlockHeaderRPKBLOCK按 StoredSize 跳过载荷
IndexTxnHeaderRPITXNBH按 BodyBytes 跳过，随后必须出现 IndexTxnFooter（RPITXNEF）
SnapshotFooterRPKSNAPF结束当前 SnapshotTxn

未知结构出现在最后一个有效 Footer 之前 → 中间损坏硬错误；之后 → 属于未提交尾部。空 DELTA（0 块）时 IndexTxnHeader 直接跟在 SnapshotHeader 之后，协议同样适用。该扫描永不需要密钥（加密 Store 的索引头 / 块目录 / Footer 均保持明文）。

打开流程

1校验 FileHeader→ 2文件尾定位最后有效 SnapshotFooter→ 3沿 PreviousFooterOffset 建立快照目录→ 4逐快照独立读取 / 校验 IndexTxn 区段并 Apply→ 5派生 SchemaIndex，发布 Store 状态
⚠️ 逐快照独立重放（R2）
某个快照的 IndexTxn 校验失败时：提交事实仍由其 Footer 决定，按 Footer 给出的 [BlocksStart, BlocksEnd) 扫描本事务数据块在内存重建索引，报告 IndexRebuiltInMemory， 然后继续处理下一个快照（不允许沿用 v1「首个坏 txn 即停、其后全部丢弃」）。重建走只读解密路径； 读写模式不原地覆盖损坏字节，由 Rewrite / 新 FULL checkpoint 收敛。
⚠️ 禁止整文件 ReadAll（R5）
单文件同时包含数据块：索引重放必须按 IndexTxn 区段 ReadAt（或依赖 mmap 按需分页）， 否则 Open 峰值内存会被放大到与数据同量级。

Footer 尾部搜索验证项

从文件尾按 8 字节对齐向前搜索 RPKSNAPF，候选必须同时通过：固定长度与 CRC ／ SnapshotEndOffset 与候选位置一致 ／ PreviousFooterOffset 严格递减且对齐 ／ SnapshotID 单调 ／ 本事务全部 offset 落在合法范围。有限窗口找不到时扩大搜索或退化为顺序扫描， 不得把较大的未提交尾部误判为无有效快照。

数据损坏

已提交范围内的 Block 块头 CRC、密文认证（GCM）、解压长度或 Raw CRC 失败 = 中间数据损坏， 必须返回错误，不得因索引可重建而跳过。

08

加密设计（AES-256-GCM）

加密在 Create 时一次性定死（头部不可变），算法 1 = AES-256-GCM，Nonce 方案 1 = CounterV1。 管道顺序：Payload → Zstd → Seal（读取逆序）。Tag 固定 16 B、Nonce 固定 96 bit，均不逐块存储。 KeyID（≤ 31 B ASCII）存于 FileHeader；密钥材料只存在于 KeyProvider，按 (KeyID, KeyEpoch) 提供 32 B 密钥。

不变量与安全上限

SnapshotFooter 区间自洽（OffsetsAreConsistent）

BlocksStartOffset = SnapshotStartOffset + 96
96+SnapshotStart ≤ BlocksStart ≤ BlocksEnd ≤ IndexTxnStart < IndexTxnEnd < SnapshotEnd
SnapshotEndOffset = IndexTxnEndOffset + 144
空事务（0 块）：BlocksEnd = IndexTxnStart = BlocksStart；FULL 允许 ParentSnapshotID = 0 且任意时刻重提；DELTA 父必须存在且 ID 更小。

10

读取路径

三种读路径全部复用同一份 Row Index，不改变磁盘块格式：

Get —— 单行点查（并发入口）

SnapshotID + TableID + RowID→ index.View.ResolveRow→ BlockID + ItemOrdinal→ Block Cache / ReadAt→ 解密 → 解压 → ParseRowAt

历史可见性沿父链解析，Tombstone（DELETE 记录）在链上覆盖旧版本。

Scan —— 顺序扫描

每层有序 Row Index 分片→ 多路归并→ 过滤覆盖记录与 Tombstone

单层 FULL 快照保留快路径。

批量读取 —— 每块只解压一次

RowIDs / Ranges→ ResolveRow→ 按 BlockID 分组去重→ 按物理 offset 排序→ 每块读取·解密·解压·校验一次→ 按 ItemOrdinal 解码多行→ 恢复 RowID / 请求顺序

重复输入 ID 重复返回（与输入下标 1:1，R17）；缺失 / 不可见行跳过，差异通过 Stats 暴露。Parallelism > 1 可并行块解码，发射顺序不变。只读调试工具 cmd/rowpack-inspect 提供 header / list / verify / dump 四个子命令。
