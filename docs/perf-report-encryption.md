# 加密性能对比报告

> 日期：2026-09-09
> 命令：`go test -run '^$' -bench 'BenchmarkEncryption$' -benchmem -benchtime=2s -count=1`
> 环境：macOS Darwin arm64 / Apple M1 Pro / Go 1.27.0 / 默认 256 KiB Block / mmap
> 场景：100k 行 × 7 列（Zstd 压缩，ratio 0.168）；batch 4096 行/批（顺序/随机交替）

## 1. 结果

| 场景 | plain | enc | 回退 | 达标(≤10%) |
| --- | --- | --- | --- | --- |
| get_hot（缓存命中点读） | 4079 kget/s | 4070 kget/s | -0.2% | ✅ |
| get_cold（无缓存随机点读） | 3.703 kget/s | 3.230 kget/s | **-12.8%** | ❌ |
| scan（顺序全表） | 7369 krows/s | 7334 krows/s | -0.5% | ✅ |
| batch（4096 行/批） | 2470 krows/s | 2467 krows/s | -0.1% | ✅ |
| write（10 万行 FULL） | 1016 krows/s | 1016 krows/s | 0% | ✅ |

冷读每次解密 256 KiB 块（约 39 µs/块，~6.5 GB/s，利用 ARM AES 指令）但只取
一行：**随机点读的解密放大是结构性成本**，与文档 §7 判断一致。其余路径
（扫描/批量/写/热读）回退 ≤ 0.5%，加密成本可忽略。

## 2. 分析

- get_hot 不回退：缓存的是解密后明文块（决策 §10.5），命中路径零解密。
- scan / batch 回退微小：块级成本被单块内多行摊薄。
- write 持平：加密与压缩均在提交的块冲水阶段，写入管道并行度未变。
- get_cold 的 -12.8% 全部来自 AES-256-GCM 每块解密；该路径当前已复用
  cipher.AEAD（每 store/key 一次密钥扩展），无按块可省开销；剩余优化
  空间（解密缓冲池、多块并行）收益不确定且语义纠缠。

## 3. 决策（2026-09-09，按选项 C）

- 按选项 A 记录基线：随机冷点读 -12.8% 属 Block 级加密的结构性解密放大
  （每次点读解密 256 KiB 块），记为已知基线；验收门槛表述定为：
  **除随机冷点读外，加密 vs 未加密吞吐回退 ≤ 10%；热路径不回退**。
- 选项 B 优化列为快速跟进项：解密缓冲池复用 / 多块并行解密 / 更小
  BlockSize 矩阵验证，仅在真实负载证明随机点读占比高时启动（由性能
  决策人确认）。
- 新增 `encrypted-store.rpk/.rpi` golden 锁定加密字节布局（格式变更
  必须同时重建该样本族）。
